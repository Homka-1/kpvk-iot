# AT-14. Проверка на сервере колледжа

Критерий AT-14 — «Приложение работает на согласованном сервере колледжа». Проверку выполняют сотрудники колледжа (сисадмин и приёмочная комиссия) на своём сервере. Разработчик готовит инструкции; результат фиксируется в этом чек-листе и в акте приёмки.

## Подготовка

1. Сисадмин заполняет чек-лист подтверждений [../deploy/server-requirements.md](../deploy/server-requirements.md).
2. Приложение устанавливается по [../deploy/install.md](../deploy/install.md) с рабочим сертификатом и доменным именем.
3. Для проверки создаются тестовые учётные записи всех ролей и тестовые группы. Реальные данные студентов вносятся только после приёмки или в отдельном рабочем экземпляре. Если проверка идёт на будущем рабочем сервере, после неё тестовые данные удаляются восстановлением пустой копии, сделанной сразу после установки, или повторной установкой с удалением томов (`docker compose down -v`, только до начала работы с реальными данными).

| 4   | Вход администратора, преподавателя, студента и исследователя; каждый видит только свои разделы | Учётные записи из раздела «Администрирование»                                               |           | ☐       |
| 5   | Критерии AT-01…AT-12 выполняются                                                               | Ручные шаги [checklist.md](checklist.md) (колонка «Как проверить вручную»)                  |           | ☐       |
| 6   | Интерфейс студента работает на смартфоне (ширина от 360 px)                                    | Сценарии AT-06 и AT-07 со смартфона                                                         |           | ☐       |
| 7   | Загрузка и скачивание файла в библиотеке материалов                                            | Преподаватель загружает PDF, студент скачивает в задании                                    |           | ☐       |

| 9   | Резервная копия создаётся по расписанию и вручную                                              | Каталог копий на следующий день; `docker compose exec backup backup.sh`                     |           | ☐       |
| 10  | Восстановление копии на тестовом стенде сервера: данные на месте                               | [../deploy/backup-restore.md](../deploy/backup-restore.md)                                  |           | ☐       |

Пункт 12 запускает нагрузочный сценарий k6 на тестовых данных. Его выполняют на тестовом экземпляре (отдельный проект Compose) или до внесения реальных данных, чтобы тестовые учётные записи не попали в рабочую базу.
