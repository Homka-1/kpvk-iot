# Ввод реальных методик и контрольных примеров

Инструкция описывает, как внести в систему диагностические методики Т. А. Ильиной, А. А. Реана, В. И. Моросановой (или другие утверждённые заказчиком) и проверить правильность расчёта на контрольных примерах (п. 4.4, п. 11.3 и огр. 1 ТЗ).

До передачи методик в системе есть только демонстрационная методика «ДЕМО — не для исследования: Учебная мотивация (пример)». Она показывает работу конструктора и не является валидированной методикой. На рабочем сервере её нет.

## 1. Что нужно получить от заказчика

Методики не придумываются и не восстанавливаются по открытым источникам: все материалы передаёт и утверждает заказчик.

| Материал                                      | Зачем                                                                                                                                   |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| Текст инструкции и всех вопросов              | Отображение студенту                                                                                                                    |
| Варианты ответов и их значения                | Подсчёт баллов                                                                                                                          |
| Шкалы и ключи                                 | Какие вопросы и варианты входят в каждую шкалу, прямой или обратный ключ, веса                                                          |
| Правила интерпретации                         | Диапазоны баллов шкалы → уровень, тексты интерпретации для преподавателя и для студента                                                 |
| Связь уровней с мотивационным профилем        | Какие уровни шкал указывают на высокий, средний или низкий мотивационный профиль                                                        |
| Паспорт                                       | Автор, назначение, возрастные ограничения, источник (выходные данные публикации), условия использования                                 |
| Подтверждение права на цифровое использование | Ограничение 1 ТЗ                                                                                                                        |
| Контрольные примеры                           | Наборы ответов с ожидаемыми баллами и уровнями по каждой шкале — не меньше трёх на методику (высокие, низкие значения, граничные баллы) |
| Правило обработки пропусков                   | Как методика учитывает пропущенные вопросы (см. [../spec/open-questions.md](../spec/open-questions.md), вопрос 15)                      |

## 2. Как система считает баллы

Методика состоит из вопросов, шкал, ключей начисления баллов и правил интерпретации. Расчёт одинаков на сервере, в предпросмотре конструктора и в автотесте контрольных примеров (`packages/shared/src/diagnostics.ts`, функция `scoreQuestionnaire`).

**Типы вопросов:**

| Тип                      | Ответ                                                       | Что даёт для расчёта               |
| ------------------------ | ----------------------------------------------------------- | ---------------------------------- |
| Шкала Лайкерта           | Целое число от минимума до максимума (не больше 11 делений) | Само число                         |
| Один вариант             | Один вариант из списка                                      | Значение выбранного варианта       |
| Несколько вариантов      | Несколько вариантов                                         | Сумма значений выбранных вариантов |
| Числовой ответ           | Число (границы — по желанию)                                | Само число                         |
| Короткий текстовый ответ | Текст                                                       | В расчёте не участвует             |

**Ключ начисления баллов** связывает шкалу с вопросом:

- **ключ по вопросу** — вклад равен ответу (см. таблицу выше), умноженному на вес;
- **обратный ключ** — вклад равен `минимум + максимум − ответ` (для шкалы Лайкерта и числового ответа — по границам вопроса, для «одного варианта» — по наименьшему и наибольшему значению вариантов), умноженному на вес. Пример: на шкале 1–5 ответ 1 даёт 5;
- **ключ по варианту** — если вариант выбран, начисляются указанные баллы (или значение варианта), иначе 0; удобно для вопросов с несколькими вариантами.

Балл шкалы — сумма вкладов всех её ключей (округление до трёх знаков после запятой).

**Пропуски.** Если хотя бы на один вопрос шкалы нет ответа, балл шкалы не рассчитывается и показывается «Нет данных»; число пропущенных вопросов сохраняется. Это правило принято до ответа заказчика (открытый вопрос 15). Если методика допускает пропуски по-другому, нужна доработка.

**Интерпретация.** Для каждой шкалы задаются уровни: «Балл от» — «Балл до» (границы включительно, одну из них можно не задавать), код и название уровня, «Вклад в мотивационный профиль» (высокий, средний, низкий или без вклада), описание для преподавателя и «Понятная студенту интерпретация». Диапазоны уровней одной шкалы не должны пересекаться. Балл, не попавший ни в один диапазон, остаётся без уровня.

**Мотивационный профиль.** Система предлагает уровень профиля, если на него указывает большинство шкал, у которых задан вклад в профиль, и таких шкал не меньше настройки «Минимум шкал для предварительного профиля». При равенстве — «Требуется дополнительная диагностика». Окончательное решение принимает преподаватель.

## 3. Ввод через конструктор (рабочий сервер)

Конструктор доступен пользователю с разрешением «Методики диагностики и их назначение» — по умолчанию преподавателю.

1. «Диагностика» → «Методики» → «Создать методику»: название и диагностическое направление (учебная мотивация, саморегуляция, академическая успешность, педагогическое наблюдение, итоговое заключение или своё — вкладка «Направления») → «Создать». Создаётся черновик версии 1.
2. Вкладка **«Паспорт»**: название, автор, назначение, возрастные ограничения, источник, «Инструкция для студента», «Условия использования», «Что изменилось в этой версии», разрешение сохранять черновик ответов.
3. Вкладка **«Вопросы»**: «Добавить вопрос», тип, текст, обязательность; для шкалы Лайкерта — границы и подписи полюсов; для вопросов с выбором — «Добавить вариант» с текстом и значением.
4. Вкладка **«Шкалы и ключи»**: «Добавить шкалу» — «Код (латиница)» (например, `COGNITIVE`), название, описание; «Добавить ключ»: вопрос, «Что учитывать» (ответ на вопрос или конкретный вариант), баллы, вес, «Обратный ключ».
5. Вкладка **«Интерпретация»**: для каждой шкалы «Добавить уровень» с диапазоном, кодом, названием, вкладом в профиль и текстами.
6. «Сохранить» — черновик сохраняется. Ошибки (вопрос без текста, ключ на несуществующий вариант, пересекающиеся диапазоны) показываются у полей.
7. «Предпросмотр» — вопросы в том виде, как их увидит студент, и блок «Расчёт по шкалам». **Введите ответы каждого контрольного примера** и сверьте баллы и уровни с ожидаемыми. Ответы предпросмотра никуда не сохраняются.
8. «Опубликовать версию» → «Опубликовать». После публикации версия неизменяема, методику можно назначать студентам.

**Изменение опубликованной методики** — только новой версией: «Создать новую версию» (черновик — копия действующей) → изменения → «Опубликовать версию». Предыдущая версия выводится из использования; её прохождения и результаты не изменяются и не пересчитываются. Замеры по разным версиям сравниваются, только если исследователь утвердит их сопоставимость ([researcher.md](researcher.md)).

Методику, которая больше не используется, можно «В архив» с причиной; «Копировать» создаёт новую методику на основе существующей.

## 4. Файл определения и автотест контрольных примеров (репозиторий)

Чтобы расчёт методики проверялся автоматически при каждом прогоне тестов, методику и её контрольные примеры добавляют в репозиторий.

### 4.1. Файл определения

`apps/api/prisma/questionnaires/<методика>/v<версия>.json`, например `apps/api/prisma/questionnaires/rean-motivation/v1.json`. Образец — `apps/api/prisma/questionnaires/demo-motivation/v1.json`.

```json
{
  "directionCode": "LEARNING_MOTIVATION",
  "isDemo": false,
  "content": {
    "title": "Название методики",
    "author": "Автор",
    "purpose": "Назначение",
    "instruction": "Инструкция для студента",
    "ageRestrictions": "Возрастные ограничения",
    "source": "Выходные данные публикации",
    "termsOfUse": "Условия использования",
    "allowDraft": true,
    "changeNote": "Первая версия",
    "questions": [
      {
        "key": "q1",
        "text": "Текст вопроса",
        "type": "LIKERT",
        "isRequired": true,
        "minValue": 1,
        "maxValue": 5,
        "minLabel": "Совсем не согласен",
        "maxLabel": "Полностью согласен",
        "options": []
      }
    ],
    "scales": [
      {
        "key": "s1",
        "code": "SCALE_CODE",
        "name": "Название шкалы",
        "description": null,
        "keys": [
          {
            "questionKey": "q1",
            "optionKey": null,
            "points": null,
            "isReverse": false,
            "weight": 1
          }
        ],
        "rules": [
          {
            "key": "r1",
            "minScore": 1,
            "maxScore": 2,
            "levelCode": "LOW",
            "levelLabel": "Низкий",
            "motivationLevel": "LOW",
            "description": "Описание для преподавателя",
            "studentText": "Понятная студенту интерпретация"
          }
        ]
      }
    ]
  }
}
```

| Поле              | Значения                                                                                                               |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `directionCode`   | `LEARNING_MOTIVATION`, `SELF_REGULATION`, `ACADEMIC_SUCCESS`, `PEDAGOGICAL_OBSERVATION`, `FINAL_CONCLUSION` или `null` |
| `isDemo`          | `false` для реальных методик                                                                                           |
| `type`            | `LIKERT`, `SINGLE_CHOICE`, `MULTIPLE_CHOICE`, `NUMBER`, `SHORT_TEXT`                                                   |
| `options[]`       | `{ "key": "q5-o1", "text": "Текст варианта", "value": 2 }` — для `SINGLE_CHOICE` и `MULTIPLE_CHOICE`                   |
| `motivationLevel` | `HIGH`, `MEDIUM`, `LOW` или `null`                                                                                     |
| `key`             | Уникальные внутри файла ключи вопросов, вариантов, шкал и правил                                                       |

Новая версия методики — новый файл `v2.json` в той же папке. Файлы определений также заполняют базу разработки командой `pnpm db:seed`: сид публикует каждую версию по порядку (если методики с таким названием версии 1 ещё нет).

### 4.2. Контрольные примеры

`apps/api/test/fixtures/diagnostics/<методика>/<версия>/<номер>-<описание>.json`, например `apps/api/test/fixtures/diagnostics/rean-motivation/1/01-high.json`:

```json
{
  "description": "Высокие значения по всем шкалам",
  "answers": {
    "q1": 5,
    "q5": "q5-o1",
    "q6": ["q6-o1", "q6-o2"],
    "q7": 10,
    "q8": "Свободный текст"
  },
  "expected": {
    "SCALE_CODE": { "rawScore": 13, "missingAnswers": 0, "levelCode": "HIGH" }
  }
}
```

- `answers` — ответы по ключам вопросов: число (Лайкерт, числовой), ключ варианта (один вариант), массив ключей (несколько вариантов), строка (текст).
- `expected` — по коду каждой шкалы: ожидаемый балл, число пропусков и код уровня. Для шкалы с пропуском: `"rawScore": null`, `"levelCode": null`.
- Номер папки версии — без буквы `v` (`1`, `2`).

### 4.3. Проверка

```sh
pnpm build:shared
pnpm --filter @iot/api test:unit -- control-examples
```

Тест `apps/api/src/diagnostics/control-examples.spec.ts` для каждого файла определения проверяет, что:

- определение проходит полную проверку публикации (как в конструкторе);
- у методики есть хотя бы один контрольный пример;
- ответы каждого примера допустимы для вопросов методики;
- рассчитанные баллы, пропуски и уровни совпадают с ожидаемыми.

Расхождение — ошибка в ключах или в примере: исправьте и повторите до полного совпадения. Тест входит в `pnpm test`.

## 5. Перенос на рабочий сервер

Сид на рабочем сервере не запускается. Проверенную методику переносят одним из способов:

1. **Через конструктор** (раздел 3) — вручную по файлу определения. После ввода прогоните контрольные примеры в «Предпросмотре».
2. **Через API** — администратор системы с учётной записью преподавателя отправляет содержимое файла запросом создания методики. Тело — `{ "directionId": "<id направления или null>", "content": <поле content из файла> }`; идентификатор направления — из `GET /api/diagnostic-directions`:

   ```sh
   jq '{directionId: null, content: .content}' apps/api/prisma/questionnaires/<методика>/v1.json > body.json
   curl -s https://<адрес сервера>/api/questionnaires \
     -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
     -H "Idempotency-Key: $(uuidgen)" -d @body.json
   ```

   Создаётся черновик версии 1. Откройте его в конструкторе, проверьте контрольные примеры в «Предпросмотре» и опубликуйте. Получение токена — [../api/README.md](../api/README.md).

## 6. Контрольный список перед использованием в исследовании

- [ ] Материалы методики и право на цифровое использование получены от заказчика.
- [ ] В названии и источнике нет пометки «ДЕМО»; паспорт заполнен полностью.
- [ ] Контрольные примеры добавлены в репозиторий, `control-examples` проходит.
- [ ] На рабочем сервере контрольные примеры совпали в «Предпросмотре».
- [ ] Версия опубликована; при изменении ключей создана новая версия, а не изменена старая.
- [ ] Правила интерпретации и вклад в мотивационный профиль утверждены заказчиком (открытый вопрос 3).
- [ ] Исследователь знает номер версии, по которой проводятся замеры.
