## Как читать таблицы

- **Шаги** — действия пользователя на приёмочном стенде (см. ниже).
- **Ожидаемый результат** — что должна показать система. Расхождение считается ошибкой.
- **Требования** — идентификаторы FR, NFR, UC, AT и пунктов ТЗ, которые проверяет сценарий.
- **Автотест** — где сценарий автоматизирован:
  - `api: <файл>` — e2e-тест API, `apps/api/test/<файл>.e2e-spec.ts` (`pnpm test`);
  - `ui: <файл>` — тест интерфейса с подменой ответов API, `apps/web/e2e/<файл>.spec.ts` (`pnpm test:e2e`);
  - `приёмка: <файл>` — сквозной тест на живом стенде, `apps/web/e2e/acceptance/<файл>.spec.ts` (`pnpm test:acceptance`);
  - `unit: <файл>` — модульный тест.

## Приёмочный стенд

Стенд — отдельная база `iot_acceptance`, API на порту 3200 и собранный интерфейс на порту 5273. Данные стенда создаются через API теми же проверками, что у пользователей (`apps/web/e2e/acceptance/support/seed.ts`):

| Данные                     | Состав                                                                                                                                                                                  |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Учётные записи сотрудников | `admin`, `teacher`, `researcher` (пароли генерируются при каждом запуске)                                                                                                               |
| Дисциплина                 | «Математика»; преподаватель `teacher` закреплён за обеими группами                                                                                                                      |
| Группы                     | «ПО-21» — экспериментальная, «ПО-22» — контрольная, по 20 студентов (AT-01). Логины `p-1001…p-1020` и `p-2001…p-2020`, общий пароль                                                     |
| Диагностика                | Демо-методика «ДЕМО — не для исследования: Учебная мотивация (пример)»; у студентов 1–10 каждой группы — первичный замер (ввод бланка) с высоким, средним или низким уровнем по очереди |
| Мотивационные профили      | Подтверждены у студентов 1–5 и 8 группы «ПО-21»                                                                                                                                         |
| ИОТ                        | Утверждены у студентов 1–5 группы «ПО-21»: пять этапов по месяцу, текущий — первый, три задания библиотеки                                                                              |
| Исследование               | «Эффективность ИОТ», статус «Проводится»: ЭГ — «ПО-21», КГ — «ПО-22», входной замер по демо-методике                                                                                    |

Студенты 11–20 обеих групп не имеют диагностики — на них проверяется работа «с нуля».

Запуск:

```sh
pnpm db:up
pnpm acceptance:stand   # стенд для ручной проверки: http://localhost:5273, остановка — Ctrl+C
pnpm test:acceptance    # автоматический прогон AT-01…AT-12 на новом стенде
```

Учётные записи и пароли стенда записываются в `apps/web/e2e/acceptance/stand.local.json` (файл не коммитится). Каждый запуск очищает базу `iot_acceptance` и заполняет её заново; базы разработки и автотестов не затрагиваются.
