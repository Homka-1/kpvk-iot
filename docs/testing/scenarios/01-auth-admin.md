# 1. Вход, роли, аудит, администрирование

Требования: п. 2, п. 8.3, MVP-1, AT-12 (частично). Роли: администратор, преподаватель, студент, исследователь.

| №    | Сценарий                           | Шаги                                                                | Ожидаемый результат                                                                                 | Требования  | Автотест                                 |
| ---- | ---------------------------------- | ------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- | ----------- | ---------------------------------------- |
| 1.1  | Вход и выход                       | Открыть любой раздел без входа; войти как `teacher`; выйти          | Без входа — страница входа; после входа — запрошенный раздел; после выхода снова нужен вход         | MVP-1       | ui: auth; api: auth                      |
| 1.2  | Неверный пароль                    | Ввести неверный пароль, затем неизвестный логин                     | Одинаковое сообщение «Неверный логин или пароль», запись в журнале аудита                           | п. 8.3      | api: auth                                |
| 1.3  | Блокировка после попыток           | Пять раз ввести неверный пароль, затем верный                       | Вход временно заблокирован даже с верным паролем                                                    | п. 8.3      | api: auth                                |
| 1.4  | Временный пароль                   | Администратор создаёт сотрудника; новый сотрудник входит            | Пока пароль не сменён, разделы недоступны; после смены — доступны                                   | MVP-1       | ui: auth; api: admin                     |
| 1.5  | Смена пароля                       | В меню профиля сменить пароль                                       | Проверяются текущий пароль и политика; другие сессии завершаются                                    | п. 8.3      | api: auth                                |
| 1.6  | Разграничение разделов             | Войти преподавателем и открыть «Администрирование» по прямой ссылке | «Нет доступа к разделу»; пункта нет в меню                                                          | п. 2, AT-12 | ui: navigation; api: admin, route-guards |
| 1.7  | Администратор и ответы диагностики | Войти администратором, открыть «Диагностика»                        | Раздела нет; API ответов диагностики отвечает 403                                                   | п. 2.1      | ui: diagnostics; api: auth, admin        |
| 1.8  | Управление пользователями          | Найти пользователя, заблокировать, разблокировать, сбросить пароль  | Блокировка сразу завершает сессии; сброс выдаёт временный пароль; администратор не меняет свои роли | п. 2.1      | api: admin                               |
| 1.9  | Разрешение исследователю на ПДн    | Выдать исследователю разрешение на ПДн с основанием, затем отозвать | Разрешение действует только после выдачи; выдача и отзыв — в журнале аудита                         | п. 2.4      | api: admin                               |
| 1.10 | Журнал аудита                      | Администрирование → Журнал: фильтр по действию и пользователю       | Записи входа, изменений и экспортов; изменить или удалить запись нельзя                             | п. 8.3      | api: admin, database                     |
| 1.11 | Настройки                          | Изменить число попыток входа до блокировки                          | Значение вне диапазона отклоняется с понятным сообщением; изменение пишется в аудит                 | п. 8.3      | api: admin                               |
| 1.12 | Персональные данные в журналах     | Выполнить вход и запросы с ошибкой                                  | В журнале запросов нет ФИО, логинов, паролей, токенов, e-mail и query-параметров                    | п. 8.3      | api: logging                             |
