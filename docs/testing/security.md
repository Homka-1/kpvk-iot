## Права на маршрутах

`apps/api/test/route-guards.e2e-spec.ts` обходит все маршруты приложения по метаданным контроллеров (более 150) и проверяет:

- без входа доступны только `GET /api/health`, `POST /api/auth/login`, `POST /api/auth/refresh`, `POST /api/auth/logout`;
- каждый остальной маршрут требует разрешения. Исключения — работа только со своими данными: `GET /api/auth/me`, `GET /api/auth/password-policy`, `POST /api/auth/change-password`, `GET /api/notifications`, `POST /api/notifications/:id/read`, `POST /api/notifications/read-all`;
- все маршруты `/api/cabinet/**` требуют ровно права кабинета студента, и ни один служебный маршрут не открывается одним этим правом;
- каждый непубличный маршрут без токена отвечает 401.

Новый маршрут без разрешения или новый публичный маршрут роняет тест — решение о доступе принимается явно.

## IDOR: доступ к чужим данным по прямой ссылке (AT-12)

`apps/api/test/idor.e2e-spec.ts` создаёт через API полный набор данных студента группы Б (преподаватель Б): ИОТ с контрольными точками, задания, выбор из равнозначных, ответ с файлом, диагностику, мотивационный профиль, наблюдение, обращение, консультацию, уведомление, материалы и файлы библиотеки. Затем:

1. Каждый маршрут с параметром в пути получает реальный идентификатор этих данных. Маршрут, для которого подстановка не задана, роняет тест, — если он не входит в список общих справочников (администрирование, группы, дисциплины, закрепления, направления диагностики, методики, сопоставимость, исследования, типы заданий): доступ к ним определяется только разрешением и проверен в тестах модулей.
2. Владелец (преподаватель Б, студент Б в кабинете) получает свои данные по всем этим ссылкам — 200. Это подтверждает, что идентификаторы настоящие.
3. Преподаватель группы А и студент группы А обращаются ко всем этим маршрутам всеми методами с корректно заполненными телами запросов. Допустимы только 403 и 404: ответ 400 или 409 означал бы, что запрос дошёл до чужих данных или не был проверен на доступ.

Результат: 0 нарушений по всем маршрутам.

## Заголовки и транспорт

Проверяет `apps/api/test/security.e2e-spec.ts`:

- `Content-Security-Policy`: `default-src 'self'`, `script-src 'self'`, `object-src 'none'`, `frame-ancestors 'none'`, `base-uri 'self'`, `form-action 'self'`; встроенные стили разрешены только для страницы документации API;
- `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Strict-Transport-Security`; заголовка `X-Powered-By` нет;
- `Cache-Control: no-store` у ответов API: персональные данные не остаются в кэше браузера и прокси;
- документация API (`/api/docs`) открывается при включённой CSP (дополнительно проверено в браузере: нарушений CSP в консоли нет);
- слишком большое тело запроса (предел JSON — 2 МБ) — 413 «Слишком большой запрос», битый JSON — 400, неизвестный маршрут — 404, файл больше 20 МБ — 413 с пояснением на русском (NFR-005).

Политика для статики интерфейса (CSP, HSTS на nginx) задаётся на этапе 21.
