# Техническое задание (текстовая копия)

> Текстовая копия `docs/spec/TZ.pdf` (версия 2.0) для работы агента. При расхождении приоритет у PDF.
> Идентификаторы FR/NFR/UC/AT используются в плане разработки (`CLAUDE.md`), тестах и журналах этапов.

**Продукт:** веб-приложение «ИОТ — цифровое сопровождение индивидуальных образовательных траекторий студентов колледжа».
**База апробации:** КГКП «Костанайский политехнический высший колледж».
**Тип:** многопользовательское веб-приложение, клиент-серверная архитектура.
**Размещение:** локальная серверная инфраструктура колледжа. **Язык интерфейса:** русский.
**Основание:** магистерское исследование о психолого-педагогических условиях реализации ИОТ для формирования учебной мотивации студентов колледжа.

## 1. Общие положения

### 1.1. Назначение
Организация, сопровождение и мониторинг ИОТ студентов организаций ТиПО. Единая цифровая среда объединяет:
психолого-педагогическую диагностику; определение мотивационного профиля; проектирование ИОТ; назначение дифференцированных заданий; педагогическое и тьюторское сопровождение; мониторинг достижений; рефлексию и обратную связь; корректировку маршрутов; анализ динамики учебной мотивации.

Приложение **не заменяет** основную СЭО колледжа и **не является** медицинским или клиническим диагностическим инструментом.

### 1.2. Цель
Цифровой инструмент, позволяющий преподавателю реализовывать индивидуальный подход к студентам с различными мотивационными характеристиками и принимать обоснованные решения на основании диагностики и мониторинга.

### 1.3. Принципы
1. Индивидуализация — маршрут учитывает особенности конкретного студента.
2. Педагогическая управляемость — окончательные решения принимает преподаватель.
3. Гибкость — применимость к любой дисциплине.
4. Непрерывность сопровождения — диагностика, обучение и обратная связь — единый процесс.
5. Прозрачность — преподаватель может объяснить основания каждой рекомендации.
6. Безопасность — персональные и диагностические данные доступны только уполномоченным.
7. Научная сопоставимость — результаты диагностик сохраняются с указанием методики, версии и времени проведения.

## 2. Роли

- **2.1. Администратор** — учётные записи, учебные группы, дисциплины, роли, настройки, техническое состояние. **Не получает** автоматического доступа к содержанию конфиденциальных диагностических ответов только на основании технической роли.
- **2.2. Преподаватель** — основной пользователь: создание/редактирование учебных материалов; назначение диагностик; анализ результатов; утверждение мотивационных профилей; создание, назначение, корректировка ИОТ; проверка заданий; обратная связь; мониторинг динамики. Работает одновременно с несколькими группами и дисциплинами.
- **2.3. Студент** — личный кабинет, диагностика, ИОТ, задания, результаты, рекомендации. **Не может** утверждать или изменять обязательные этапы ИОТ; **может** выбирать доступные варианты заданий, указывать интересы, запрашивать помощь, предлагать изменения.
- **2.4. Исследователь** — обезличенные результаты, групповая аналитика, данные первичной и повторной диагностики, экспорт. Просмотр персональных данных — отдельно, только при наличии правовых оснований.

## 4. Функциональные требования

### 4.1. Главная панель преподавателя
Назначение: оперативная информация о состоянии ИОТ.
- Верх: название системы; имя и роль пользователя; выбранная группа; выбранная дисциплина; уведомления.
- Слева: постоянное навигационное меню.
- Центр — карточки: количество студентов; активных ИОТ; средний % выполнения маршрутов; заданий на проверку; просроченных заданий; студентов, требующих внимания.
- Ниже: диаграмма выполнения ИОТ; распределение мотивационных профилей; последние задания; последняя активность; предстоящие контрольные точки.

- **FR-001.** Данные панели автоматически обновляются после изменения результатов обучения.
- **FR-002.** Все показатели рассчитываются только по доступным преподавателю студентам.
- **FR-003.** Нажатие на показатель открывает соответствующий отфильтрованный список.
- **FR-004.** Переключение группы, дисциплины и периода наблюдения.
- **FR-005.** При отсутствии данных — пояснение, а не фиктивные показатели.

### 4.2. Студенты
Карточка: Ф. И. О. или код участника; группа; курс; специальность; мотивационный профиль; текущая ИОТ; прогресс маршрута; средний показатель успеваемости; количество выполненных заданий; дата последней активности; статус сопровождения.
- **FR-006.** Добавление вручную или импортом из CSV/XLSX.
- **FR-007.** Поиск по фамилии, коду участника и группе.
- **FR-008.** Фильтрация по мотивационному профилю, дисциплине, статусу ИОТ и наличию затруднений.
- **FR-009.** Просмотр полной карточки студента.
- **FR-010.** Перевод в другую группу без удаления истории.
- **FR-011.** Архивирование профиля с сохранением исследовательских данных в пределах сроков хранения.

### 4.3. Профиль студента
Вкладки: **Общие сведения** (группа, курс, специальность, дисциплины, преподаватели); **Диагностика** (результаты методик, даты, динамика); **Мотивационный профиль** (уровень, характеристики, рекомендации); **Моя ИОТ** (цели, этапы, прогресс); **Задания** (выполненные, активные, просроченные); **Сопровождение** (консультации, рекомендации, комментарии); **История** (значимые изменения маршрута и результатов).
- **FR-012.** Данные собираются из модулей автоматически.
- **FR-013.** Исходные ответы диагностики нельзя изменять после завершения без отдельной процедуры исправления ошибочного ввода.
- **FR-014.** Преподаватель добавляет педагогические наблюдения с датой и авторством.
- **FR-015.** Профиль показывает динамику, а не только последнее значение.
- **FR-016.** Студенту — понятная педагогическая интерпретация без закрытых служебных заметок преподавателя.

### 4.4. Диагностика
Конструктор методик (уполномоченный пользователь): название; автор; назначение; инструкция; возрастные ограничения; перечень вопросов; типы ответов; правила начисления баллов; шкалы; правила интерпретации; версия; источник; условия использования.
Типы вопросов: один вариант; несколько вариантов; шкала Лайкерта; числовой ответ; короткий текстовый ответ.
- **FR-017.** Создание, редактирование, копирование, архивирование методик.
- **FR-018.** Назначение методики одному студенту или группе.
- **FR-019.** Установка периода прохождения.
- **FR-020.** Автоматическое вычисление результатов по утверждённым ключам.
- **FR-021.** Обратное кодирование и расчёт нескольких шкал.
- **FR-022.** Ручной ввод результатов бумажной диагностики.
- **FR-023.** Сохранение даты, версии методики, исходных ответов и рассчитанных баллов.
- **FR-024.** Сравнение результатов повторных замеров.
- **FR-025.** Выгрузка результатов в обезличенном виде.
- **FR-026.** При изменении ключей создаётся новая версия методики. Старые прохождения не пересчитываются без явно инициированной и документированной процедуры.

Диагностические направления (настраиваемые разделы): учебная мотивация; саморегуляция; академическая успешность; педагогическое наблюдение; итоговое аналитическое заключение.
Первоначальное наполнение — методики программы исследования (Т. А. Ильина, А. А. Реан, В. И. Моросанова). Тексты, ключи и правила обработки передаёт заказчик после проверки допустимости цифрового использования.

### 4.5. Мотивационные профили
Назначение: преобразование результатов диагностики в педагогические рекомендации.
- **Высокий уровень:** самостоятельность, исследовательские задания, проекты повышенной сложности, профессиональные конкурсы.
- **Средний уровень:** развитие самостоятельности, постепенное усложнение, практические задания, предоставление выбора.
- **Низкий уровень:** небольшие достижимые цели, пошаговая работа, регулярная поддержка, обратная связь, создание ситуации успеха.

- **FR-027.** Предварительный профиль на основании утверждённых правил интерпретации.
- **FR-028.** Отображение показателей, повлиявших на рекомендацию.
- **FR-029.** Педагогическая корректировка предложенного профиля с указанием причины.
- **FR-030.** Три карточки профилей и соответствующие стратегии сопровождения.
- **FR-031.** Кнопка «Сформировать ИОТ» — переход к конструктору маршрута.
- **FR-032.** История изменения профиля.
- **FR-033.** Нет автоматического ограничения сложности заданий только по уровню мотивации.

При недостаточности данных — статус «Требуется дополнительная диагностика», профиль произвольно не присваивается.

### 4.6. Индивидуальные образовательные траектории
Паспорт ИОТ: уникальный идентификатор; студент; дисциплина; преподаватель; мотивационный профиль на момент назначения; образовательные цели; планируемые результаты; дата начала; планируемая дата завершения; текущий этап; статус; версия маршрута.

Пятиэтапная модель (стандартный шаблон; преподаватель адаптирует продолжительность, содержание и результаты):
1. **Адаптационный** — знакомство с образовательными задачами, выявление затруднений, постановка достижимых целей.
2. **Развитие учебной самостоятельности** — планирование деятельности, выбор заданий, освоение способов самоконтроля.
3. **Практико-ориентированная деятельность** — решение профессиональных и прикладных задач.
4. **Проектная деятельность** — индивидуальные или групповые проекты, представление результатов.
5. **Профессиональное развитие** — самооценка компетенций, дальнейшее образовательное планирование, развитие профессиональных интересов.

- **FR-034.** Создание ИОТ из шаблона или с нуля.
- **FR-035.** Автоматическое предложение шаблона на основании мотивационного профиля.
- **FR-036.** Редактирование целей, сроков, этапов, заданий и способов сопровождения.
- **FR-037.** Назначение образовательных материалов каждому этапу.
- **FR-038.** Предварительный просмотр маршрута перед утверждением.
- **FR-039.** Утверждение маршрута исключительно преподавателем с соответствующими правами.
- **FR-040.** Публикация утверждённой ИОТ в кабинете студента.
- **FR-041.** Визуальная карта маршрута.
- **FR-042.** Учёт выполнения каждого этапа.
- **FR-043.** Корректировка маршрута с сохранением предыдущей версии.
- **FR-044.** Завершение маршрута с итоговой оценкой достижения целей.
- **FR-045.** Несколько ИОТ у одного студента по разным дисциплинам.

Статусы: «Черновик», «На утверждении», «Активна», «Требует корректировки», «Завершена», «Архивирована». В первой версии «На утверждении» используется только при необходимости дополнительного согласования; обязательный утверждающий — преподаватель.

### 4.7. Задания

Типы: практическая работа, лабораторная работа, кейс, мини-проект, исследовательское задание, презентация, творческая работа, самостоятельная работа и другие настраиваемые типы.
- **FR-046.** Создание и редактирование заданий.
- **FR-047.** Библиотека заданий с поиском по дисциплине, теме и уровню сложности.
- **FR-048.** Назначение отдельному студенту, нескольким студентам или группе.
- **FR-049.** Прикрепление файлов, ссылок и инструкций.

### 4.8. Мониторинг
Показатели: доля выполненных заданий; достижение контрольных точек; выполнение образовательных целей; динамика академической успешности; результаты повторной диагностики; активность студента; обращения за помощью; количество корректировок маршрута.
- **FR-056.** Прогресс в процентах.
- **FR-057.** Фильтрация по студентам, дисциплинам, группам и периодам.
- **FR-058.** Предупреждения о просроченных заданиях и пропущенных контрольных точках.
- **FR-059.** Динамика показателей в графическом виде.
- **FR-060.** Преподаватель отмечает необходимость дополнительного сопровождения.
- **FR-061.** Переход из мониторинга к корректировке ИОТ.

### 4.10. Аналитика

Исследовательский режим: создание исследования; исследовательские коды участникам; экспериментальная и контрольная группы; фиксация первичного и повторного замеров; сравнение по одинаковым шкалам; экспорт исходных и агрегированных данных.

## 5. Пользовательские сценарии

- **UC-01. Первичная диагностика** (преподаватель, студент). Предусловие: студент зарегистрирован, методика настроена и опубликована. 1) «Диагностика» → 2) методика и группа → 3) период → 4) «Назначить» → 5) студент получает уведомление → 6) открывает опросник, читает инструкцию → 7) отвечает → 8) подтверждает завершение → 9) система проверяет полноту и рассчитывает показатели → 10) преподаватель видит результат в профиле студента. Альтернатива: при обрыве соединения ответы восстанавливаются из черновика, если это допускает настройка методики. Результат: диагностическая сессия с результатами и временем прохождения.
- **UC-02. Формирование мотивационного профиля** (преподаватель). Профиль студента → результаты диагностики → данные наблюдения и успеваемости → «Мотивационные профили» → предложенный профиль и основания → подтвердить или скорректировать с обоснованием → сохранить. Результат: профиль доступен для проектирования ИОТ.
- **UC-03. Создание и утверждение ИОТ** (преподаватель). Карточка студента → «Создать ИОТ» → дисциплина → шаблон по профилю → цели → настройка пяти этапов → задания и ресурсы → сроки и контрольные точки → формы поддержки → предварительный просмотр → «Утвердить и назначить». Результат: статус «Активна», ИОТ видна студенту.
- **UC-04. Выполнение задания** (студент). Вход → «Моя траектория» → текущий этап → задание → инструкция и критерии → выполнение → прикрепление результата → «Отправить на проверку» → оценка и комментарий. Результат: результат сохранён, прогресс ИОТ обновлён.
- **UC-05. Корректировка ИОТ** (преподаватель). «Мониторинг» → затруднения студента → задания, диагностика, история сопровождения → консультация → действующая ИОТ → «Корректировать» → изменить сроки/задания/уровень поддержки/последовательность → причина → подтвердить новую версию. Результат: предыдущая версия сохранена, студент уведомлён.
- **UC-06. Повторная диагностика** (преподаватель, студент). Назначение повторного замера → прохождение той же версии или сопоставимой, утверждённой исследователем → расчёт → показатели первичного и повторного замеров → анализ → при необходимости корректировка ИОТ. Результат: сохранена динамика.
- **UC-07. Экспорт данных исследования** (исследователь). «Аналитика» → исследование → группы КГ и ЭГ → шкалы и периоды → таблица → количество полных и неполных наблюдений → «Экспортировать» → обезличенный файл. Результат: набор данных для статистической обработки.

## 6. Требования к интерфейсам

- **6.1. Общий дизайн:** академический стиль; светлая схема; тёмно-синие заголовки; светло-голубые информационные блоки; сдержанные цветовые индикаторы; карточная структура; единообразные кнопки и поля; адаптивная сетка; понятная визуализация прогресса. Цвет не должен быть единственным способом передачи статуса.
- **6.2. Панель преподавателя:** слева вертикальное меню; сверху название, группа, дисциплина, профиль; под шапкой сводные показатели; ниже две диаграммы; внизу задания и активность.
- **6.3. Профиль студента:** верхняя карточка с основными сведениями; вкладки диагностики и мотивационного профиля; центральная карта ИОТ; графики динамики; список заданий; блок педагогических рекомендаций.
- **6.4. Экран ИОТ:** главный элемент — последовательная карта пяти этапов. Для каждого этапа: название, цель, сроки, статус, % выполнения, количество заданий, контрольная точка. При выборе этапа открывается подробное содержание.
- **6.5. Кабинет студента:** первый экран отвечает на вопросы: 1) Какая моя текущая цель? 2) Что мне нужно выполнить сейчас? 3) Чего я уже достиг? 4) Где получить помощь? Избегать перегруженности сложной аналитикой.

## 8. Техническая архитектура

### 8.1. Стек
Frontend: Vue 3, TypeScript, Vite. Backend: Laravel или NestJS (выбор разработчика; **выбран NestJS**). БД: PostgreSQL. Web-сервер: Nginx. API: REST + OpenAPI. Развёртывание: Linux-сервер колледжа, предпочтительно контейнеры. Файлы: защищённое локальное или совместимое объектное хранилище внутри инфраструктуры колледжа.

### 8.2. Сервер колледжа
Сисадмин подтверждает: выделенный сервер/ВМ; ресурсы; защищённый сетевой доступ; HTTPS; доменное имя или внутренний адрес; резервное копирование; порядок обновления; доступность для студентов вне колледжа (если предусмотрено). Ориентир для пилота: 2–4 vCPU, 8 ГБ RAM, 50–100 ГБ диска.

### 8.3. Безопасность (обязательно)
Шифрование соединения; безопасное хранение паролей; разграничение прав на сервере; защита от SQL-инъекций, XSS, CSRF; ограничение попыток входа; контроль загрузки файлов; журналирование изменений ИОТ и диагностических данных; резервное копирование; проверка восстановления из копии; отсутствие ПДн в открытых журналах ошибок. Обработка ПДн — с учётом законодательства РК и внутренних документов колледжа.

## 14. Ограничения
1. Методики и правила интерпретации утверждаются заказчиком до публикации.
2. Приложение не принимает окончательных педагогических решений без преподавателя.
3. Мотивационные профили — для организации поддержки, не для ограничения возможностей.
4. Контрольная группа в исследовательском режиме **не получает** экспериментальные ИОТ.
5. Исходные диагностические данные и история маршрутов хранятся по установленной политике хранения.
6. Функции вне MVP — только после отдельного согласования.
7. Изменение внешнего вида не нарушает структуру и логику макета без согласования с заказчиком.

## 15. Ожидаемый результат
Работающее веб-приложение полного цикла цифрового психолого-педагогического сопровождения ИОТ: переход от диагностики к педагогическим действиям, сопровождение маршрута, фиксация достижений, обоснованная корректировка обучения; для исследования — достоверная регистрация процедур и экспорт сопоставимых данных для оценки эффективности ИОТ.
