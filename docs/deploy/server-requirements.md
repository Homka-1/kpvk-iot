# Требования к серверу

Требования и перечень того, что системный администратор колледжа подтверждает до установки (п. 8.2 ТЗ).

## Аппаратные ресурсы

| Ресурс | Пилот (до 50 одновременных пользователей, NFR-001) | Примечание                                                                |
| ------ | -------------------------------------------------- | ------------------------------------------------------------------------- |
| CPU    | 2–4 vCPU                                           | Нагрузочный тест (`docs/testing/load.md`) — p95 основных экранов ≤ 1,7 с  |
| RAM    | 8 ГБ                                               | Контейнеры, кэш PostgreSQL и ОС, запас на формирование отчётов            |
| Диск   | 50–100 ГБ SSD                                      | База, загруженные файлы (до 20 МБ каждый), образы Docker, резервные копии |

Объём резервных копий: каждая копия — это дамп базы плюс архив всех загруженных файлов. При 14 хранимых копиях отведите под каталог копий не меньше 14 × (размер базы + размер файлов) с запасом. Каталог копий лучше разместить на отдельном диске или периодически переносить на другой сервер.

## Программное обеспечение

- 64-битный Linux (Ubuntu Server 22.04/24.04 LTS, Debian 12 или совместимый), архитектура x86_64.
- Docker Engine 24 или новее с плагином Docker Compose v2 (`docker compose version`).
- Git — для получения кода и обновлений (либо архив выпуска).
- OpenSSL — для самоподписанного сертификата тестового стенда.
- Синхронизация времени (chrony или systemd-timesyncd): от времени зависят сроки заданий, токены входа и расписание копий.

Устанавливать Node.js, PostgreSQL и nginx на сам сервер не нужно: всё работает в контейнерах.

## Сеть

- Входящие порты: 443/TCP (HTTPS) и 80/TCP (только перенаправление на HTTPS). Другие порты наружу не открываются.
- Исходящий доступ в интернет нужен только при сборке образов (загрузка базовых образов и пакетов npm). Если на сервере интернета нет, образы собираются на другой машине и переносятся (`docker save` / `docker load`).
- Доменное имя или внутренний адрес, по которому пользователи открывают систему.
- Сертификат TLS для этого имени: от удостоверяющего центра, корпоративного центра колледжа или Let's Encrypt. Самоподписанный сертификат допустим только для тестового стенда.

## Чек-лист подтверждений сисадмина (п. 8.2)

| №   | Что подтверждается                                                                               | Отметка |
| --- | ------------------------------------------------------------------------------------------------ | ------- |
| 1   | Выделен сервер или виртуальная машина под систему                                                | ☐       |
| 2   | Ресурсы не ниже ориентира пилота: 2–4 vCPU, 8 ГБ RAM, 50–100 ГБ диска                            | ☐       |
| 3   | Установлены Docker Engine и Docker Compose v2; время синхронизируется                            | ☐       |
| 4   | Защищённый сетевой доступ: открыты только 80 и 443, администрирование по SSH с ключами           | ☐       |
| 5   | HTTPS: сертификат и ключ для доменного имени выданы и размещены на сервере                       | ☐       |
| 6   | Доменное имя или внутренний адрес согласован и настроен в DNS                                    | ☐       |
| 7   | Резервное копирование: место под копии, расписание, перенос копий на другой носитель             | ☐       |
| 8   | Порядок обновления согласован: кто, когда и как обновляет, окно обслуживания                     | ☐       |
| 9   | Решено, доступна ли система студентам вне сети колледжа, и если да — как (публикация, VPN)       | ☐       |
| 10  | Обработка персональных данных соответствует законодательству РК и внутренним документам колледжа | ☐       |
