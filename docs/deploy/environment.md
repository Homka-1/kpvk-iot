# Переменные окружения

Рабочее окружение настраивается файлом `.env.prod` в корне репозитория (образец — `.env.prod.example`). Файл содержит секреты: не коммитьте его и ограничьте доступ (`chmod 600 .env.prod`). Docker Compose читает его ключом `--env-file .env.prod`.

| Переменная               | Обязательна | По умолчанию     | Назначение                                                                                                                                          |
| ------------------------ | ----------- | ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `IOT_VERSION`            | нет         | `local`          | Метка собранных образов (`iot-api:<метка>`). Удобно ставить дату или номер выпуска: по метке видно, какая версия работает, и проще откатиться.      |
| `POSTGRES_USER`          | нет         | `iot`            | Пользователь базы данных                                                                                                                            |
| `POSTGRES_PASSWORD`      | **да**      | —                | Пароль базы. Только латинские буквы и цифры: он входит в строку подключения. Пример: `openssl rand -hex 24`                                         |
| `POSTGRES_DB`            | нет         | `iot`            | Имя базы данных                                                                                                                                     |
| `JWT_SECRET`             | **да**      | —                | Секрет подписи токенов входа, не короче 32 символов, свой для каждого окружения. Пример: `openssl rand -hex 32`. Смена секрета завершает все сеансы |
| `JWT_ACCESS_TTL_SECONDS` | нет         | `900`            | Срок жизни access-токена, секунды                                                                                                                   |
| `LOGIN_RATE_LIMIT`       | нет         | `20`             | Число запросов входа с одного адреса в минуту                                                                                                       |
| `LOG_LEVEL`              | нет         | `info`           | Уровень журнала API: `error`, `warn`, `info`, `debug`                                                                                               |
| `HTTP_PORT`              | нет         | `80`             | Порт сервера для HTTP (только перенаправление на HTTPS)                                                                                             |
| `HTTPS_PORT`             | нет         | `443`            | Порт сервера для HTTPS                                                                                                                              |
| `TLS_CERT_DIR`           | нет         | `./deploy/certs` | Каталог с `fullchain.pem` (сертификат с цепочкой) и `privkey.pem` (ключ)                                                                            |
| `BACKUP_SCHEDULE`        | нет         | `30 2 * * *`     | Расписание резервного копирования в формате cron (минута, час, день, месяц, день недели), время по `TZ`                                             |
| `BACKUP_KEEP`            | нет         | `14`             | Сколько последних копий хранить; более старые удаляются после каждой новой копии                                                                    |
| `BACKUP_HOST_DIR`        | нет         | `./backups`      | Каталог копий на сервере                                                                                                                            |
| `TZ`                     | нет         | `Asia/Almaty`    | Часовой пояс расписания копий и имён каталогов копий                                                                                                |

Переменные, которые задаются в `docker-compose.standalone.yml` и менять не нужно:

- `NODE_ENV=production` — cookie сеанса только по HTTPS (`Secure`).
- `TRUST_PROXY=1` — API находится за одним обратным прокси (nginx) и берёт адрес клиента из заголовка `X-Forwarded-For`, который nginx перезаписывает. Адрес нужен ограничению попыток входа и журналу аудита. Без прокси переменную не задают: тогда заголовок присылает сам клиент и доверять ему нельзя.
- `DATABASE_URL` — собирается из `POSTGRES_*`.
- `FILE_STORAGE_DIR=/var/lib/iot/files` — каталог загруженных файлов в контейнере API (том `files`).
