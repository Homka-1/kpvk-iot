# Установка

Установка на подготовленный сервер (см. [server-requirements.md](server-requirements.md)). Все команды выполняются из корня репозитория пользователем, которому разрешено запускать Docker.

## 1. Код

```sh
git clone <адрес репозитория> /opt/iot
cd /opt/iot
git checkout <метка выпуска или main>
```

Без доступа к репозиторию с сервера распакуйте архив выпуска в `/opt/iot`.

## 2. Сертификат

Положите сертификат и ключ в `deploy/certs/` (каталог не коммитится):

- `deploy/certs/fullchain.pem` — сертификат сервера вместе с промежуточными сертификатами;
- `deploy/certs/privkey.pem` — закрытый ключ.

nginx в контейнере работает от пользователя с UID 101, поэтому ключ должен быть ему доступен на чтение, а остальным — нет:

```sh
sudo chown 101:101 deploy/certs/privkey.pem
sudo chmod 600 deploy/certs/privkey.pem
```

Для тестового стенда можно создать самоподписанный сертификат (браузер покажет предупреждение):

```sh
docker/nginx/self-signed-cert.sh deploy/certs iot.college.local
```

## 3. Переменные окружения

```sh
cp .env.prod.example .env.prod
chmod 600 .env.prod
```

В `.env.prod` обязательно задайте `POSTGRES_PASSWORD` и `JWT_SECRET`:

```sh
echo "POSTGRES_PASSWORD=$(openssl rand -hex 24)"
echo "JWT_SECRET=$(openssl rand -hex 32)"
```

Остальные переменные и их значения по умолчанию — [environment.md](environment.md). Сохраните копию `.env.prod` в надёжном месте: без `POSTGRES_PASSWORD` не подключиться к базе из резервной копии тома, а смена `JWT_SECRET` завершает все сеансы.

## 4. Сборка и запуск

```sh
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --build --wait
```

Первая сборка занимает несколько минут. При старте API сам применяет миграции к пустой базе. Ключ `--wait` дожидается, пока все контейнеры станут здоровыми (`healthy`); проверить состояние можно так:

```sh
docker compose -f docker-compose.prod.yml --env-file .env.prod ps
curl -k https://localhost/api/health      # {"status":"ok"}
```

Чтобы не набирать параметры каждый раз, можно задать их в окружении оболочки администратора:

```sh
export COMPOSE_FILE=docker-compose.prod.yml COMPOSE_ENV_FILES=.env.prod
docker compose ps
```

Контейнеры перезапускаются автоматически после сбоя и перезагрузки сервера (`restart: unless-stopped`), если служба Docker включена: `sudo systemctl enable docker`.

## 5. Первая учётная запись администратора

На рабочем сервере демо-данные не загружаются. Администратор создаётся командой в контейнере API:

```sh
docker compose -f docker-compose.prod.yml --env-file .env.prod exec api node dist/cli/create-admin.js
```

Команда выводит временный пароль один раз. При первом входе система попросит сменить его. Другой логин — аргументом: `... create-admin.js ivanov.admin`. Повторный запуск с существующим логином ничего не меняет. Создание записывается в журнал аудита.

Дальше администратор в разделе «Администрирование» создаёт учётные записи преподавателей и исследователей, группы и дисциплины; преподаватели добавляют студентов (вручную или импортом CSV/XLSX).

## 6. Методики диагностики

В системе нет методик, пока их не внесут. Реальные методики (Ильина, Реан, Моросанова) вносятся через конструктор методик после передачи заказчиком; демо-методика с пометкой «ДЕМО — не для исследования» есть только в демо-данных разработки.

## 7. Проверка после установки

1. Откройте `https://<имя сервера>/` — страница входа без предупреждений о сертификате (для рабочего сертификата).
2. `http://<имя сервера>/` перенаправляет на HTTPS.
3. Вход администратором, смена временного пароля, разделы «Администрирование» и «Настройки» открываются.
4. Документация API — `https://<имя сервера>/api/docs`.
5. Сделайте первую резервную копию вручную и убедитесь, что она появилась в каталоге копий ([backup-restore.md](backup-restore.md)).
6. Пройдите проверку AT-14 ([../acceptance/at-14-server.md](../acceptance/at-14-server.md)).
