# Развёртывание через Coolify

Coolify получает код из закрытого репозитория GitHub по deploy key, собирает образы на сервере и обновляет приложение после каждого пуша в ветку `main`. Используется файл `docker-compose.prod.yml`; скрипт `scripts/deploy.sh` при этом не нужен.

Отличия от установки по [install.md](install.md):

- HTTPS, сертификат и домен обслуживает прокси перед приложением, его настраивает администратор сервера. `nginx` приложения принимает от прокси HTTP на порту сервера `HTTP_PORT` (тот же номер внутри контейнера) и делит запросы между API и интерфейсом. Конфигурация nginx входит в образ (`docker/nginx/coolify.conf.template`), порт подставляется при старте контейнера: Coolify не монтирует файлы репозитория в контейнеры.
- Перед API два прокси (внешний и `nginx`), поэтому `TRUST_PROXY=2`. Внешний прокси должен передавать `X-Forwarded-For` и `X-Forwarded-Proto`. Порт `HTTP_PORT` закройте файрволом для всех, кроме прокси: при прямом обращении клиент может подставить свой адрес в `X-Forwarded-For` и обойти ограничение попыток входа.
- Резервное копирование **временно отключено** по решению администратора сервера: сервиса `backup` в файле нет. Чтобы вернуть его, перенесите сервис `backup` из `docker-compose.standalone.yml`, указав вместо переменной `BACKUP_HOST_DIR` абсолютный путь (Coolify не допускает переменных в путях томов).
- Переменные окружения задаются в интерфейсе Coolify, файл `.env.prod` не используется.
- Имена проекта, сетей и томов назначает Coolify. Тома `pgdata` и `files` сохраняются между обновлениями.

## Настройка ресурса

1. **New Resource → Private Repository (with Deploy Key)**: репозиторий `git@github.com:Homka-1/kpvk-iot.git`, ветка `main`, ключ, добавленный в репозиторий (Settings → Deploy keys, без права записи).
2. **Build Pack**: Docker Compose; **Docker Compose Location**: `/docker-compose.prod.yml`.
3. **Адрес сайта**: прокси администратора принимает домен на 80/443 (сертификат — на прокси) и направляет запросы на `http://<сервер>:<HTTP_PORT>`. Домены сервисам в Coolify не назначаются.

   Без HTTPS вход не работает: cookie сессии передаётся только по HTTPS.

4. **Environment Variables**:

   | Переменная                     | Значение                                                                                          |
   | ------------------------------ | ------------------------------------------------------------------------------------------------- |
   | `POSTGRES_PASSWORD`            | обязательна; только латинские буквы и цифры: `openssl rand -hex 24`                               |
   | `JWT_SECRET`                   | обязательна; не короче 32 символов: `openssl rand -hex 32`                                        |
   | `HTTP_PORT`                    | по умолчанию `8081`; свободный порт на сервере, на который прокси направляет запросы              |
   | `POSTGRES_USER`, `POSTGRES_DB` | по умолчанию `iot`                                                                                |
   | остальные                      | как в [environment.md](environment.md): `JWT_ACCESS_TTL_SECONDS`, `LOGIN_RATE_LIMIT`, `LOG_LEVEL` |

   Сохраните копию `POSTGRES_PASSWORD` и `JWT_SECRET` вне Coolify: без пароля не восстановить базу из тома. После первого запуска `POSTGRES_PASSWORD` не меняют — PostgreSQL задаёт пароль только при создании тома. У секретов снимите отметку **Build Variable**: при сборке они не нужны.

5. **Auto Deploy** включён: Coolify обновляет приложение по вебхуку GitHub при пуше в `main`. Если сервер недоступен из интернета, вебхук не дойдёт — тогда обновление запускают кнопкой **Deploy** или через API Coolify.
6. **Deploy**. При первом запуске API создаёт структуру базы миграциями. Проверка: `https://<домен>/api/health` отвечает `200`.

## Первый администратор

В Coolify: **Terminal**, контейнер `api`:

```sh
node dist/cli/create-admin.js admin
```

Временный пароль выводится один раз; при первом входе его нужно сменить.

## Обновление

Каждый пуш в `main` собирает новые образы и перезапускает контейнеры; API применяет новые миграции при старте (NFR-007). Установка зависимостей берётся из кэша сборки Docker и повторяется только при изменении `pnpm-lock.yaml` или списков зависимостей в `package.json` (подъём `version` кэш не сбрасывает), поэтому не включайте в настройках ресурса **Disable Build Cache**. Пока резервное копирование отключено, перед пушем с новыми миграциями сделайте копию базы вручную, например в терминале контейнера `postgres`:

```sh
pg_dump -U iot -d iot -Fc -f /tmp/before-update.dump
```

и перенесите файл с сервера (`docker cp`).

Если новая версия не стала здоровой, причина — в журнале развёртывания и в логах сервиса `api` в Coolify. Откат: повторное развёртывание прежнего коммита (**Rollback** или пуш с возвратом изменений). Если новая версия успела применить миграции, откат выполняется вместе с восстановлением копии — см. [update.md](update.md), раздел «Откат».

Новые переменные из `.env.prod.example` добавляйте в Coolify до пуша, который их использует: иначе развёртывание завершится ошибкой.
