## Состав

Приложение запускается Docker Compose. Рабочий сервер колледжа использует Coolify и файл `docker-compose.prod.yml` ([coolify.md](coolify.md)): `nginx` принимает HTTP на порту сервера из переменной `HTTP_PORT`, HTTPS и домен обслуживает прокси администратора сервера, резервное копирование пока отключено. На сервере без Coolify используется `docker-compose.standalone.yml` ([install.md](install.md)), в котором `nginx` сам обслуживает HTTPS. Остальное у файлов общее. Пять контейнеров:

| Сервис     | Образ                                     | Назначение                                                                                   |
| ---------- | ----------------------------------------- | -------------------------------------------------------------------------------------------- |
| `nginx`    | `nginxinc/nginx-unprivileged:1.30-alpine` | Единственная точка входа: HTTPS, перенаправление с HTTP, HSTS, сжатие, лимит загрузки 25 МБ  |
| `web`      | `iot-web` (`docker/web/Dockerfile`)       | Статика интерфейса (production-сборка Vue), заголовки безопасности страниц                   |
| `api`      | `iot-api` (`docker/api/Dockerfile`)       | REST API (NestJS); при старте применяет новые миграции базы; загруженные файлы — том `files` |
| `postgres` | `postgres:16-alpine`                      | База данных, том `pgdata`                                                                    |
| `backup`   | `iot-backup` (`docker/backup/Dockerfile`) | Резервные копии базы и файлов по расписанию с ротацией; восстановление                       |

```
браузер ──HTTPS──▶ nginx ──▶ web   (статика)
                     └────▶ api ──▶ postgres
                               └──▶ том files ◀── backup ──▶ каталог копий на сервере
```

- Сеть `backend` внутренняя: база и API недоступны снаружи, к ним обращается только nginx. Наружу открыты только порты nginx (по умолчанию 80 и 443).
- Контейнеры `api`, `web` и `nginx` работают без прав root и без дополнительных привилегий Linux. Контейнер `backup` работает от root: он читает и восстанавливает файлы тома `files` с их владельцем.
- Журналы контейнеров ограничены: до 5 файлов по 10 МБ на контейнер. Персональные данные в журнал API не попадают (маскирование, п. 8.3).

## Окружения

Рабочее окружение полностью отделено от разработки и тестов (NFR-010):

| Окружение            | Как запускается                                         | База данных               | Файлы                 |
| -------------------- | ------------------------------------------------------- | ------------------------- | --------------------- |
| Разработка           | `pnpm dev`, база из `docker-compose.dev.yml`            | `iot_dev`                 | `storage/development` |
| Автотесты            | `pnpm test`, `pnpm test:e2e`                            | `iot_test`                | `storage/test`        |
| Приёмочный стенд     | `pnpm acceptance:stand`, `pnpm test:acceptance`         | `iot_acceptance`          | `storage/acceptance`  |
| Тест восстановления  | `pnpm test:restore` (проект Compose `iot-at13`)         | временный том             | временный том         |
| Рабочее (production) | Coolify: `docker-compose.prod.yml` + переменные Coolify | том `pgdata` (база `iot`) | том `files`           |
| Сервер без Coolify   | `docker-compose.standalone.yml` + `.env.prod`           | том `pgdata` (база `iot`) | том `files`           |

Для тестового сервера колледжа используйте отдельную копию репозитория (или другое имя проекта Compose, `-p iot-test`) со своим `.env.prod`, своими секретами и портами: тома разных проектов Compose не пересекаются.
