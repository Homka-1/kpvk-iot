# Документация API

Сервер приложения предоставляет REST API в формате JSON. Им пользуется веб-интерфейс; тем же API можно пользоваться из других программ колледжа при наличии учётной записи с нужными разрешениями.

## Где взять описание

| Источник                                        | Что это                                                                                                        |
| ----------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| [openapi.json](openapi.json)                    | Полное описание API в формате OpenAPI 3: все маршруты, параметры, тела запросов и ответов, коды ошибок         |
| `https://<адрес сервера>/api/docs`              | Интерактивная страница документации (Swagger UI) работающего сервера: можно выполнить запрос прямо из браузера |
| `https://<адрес сервера>/api/docs/openapi.json` | То же описание, что в `openapi.json`, выдаваемое работающим сервером                                           |

Файл `openapi.json` в репозитории формируется из кода командой `pnpm docs:openapi` (база данных не нужна). Автотест `apps/api/test/health.e2e-spec.ts` сверяет файл с описанием работающего API: если маршруты изменились, а файл не обновлён, тест падает.

## Общие правила

- **Адрес.** Все маршруты начинаются с `/api`. На рабочем сервере API доступен только через HTTPS за обратным прокси (см. [../deploy/README.md](../deploy/README.md)).
- **Формат.** Запросы и ответы — JSON в кодировке UTF-8; даты — ISO 8601 (`2026-10-20` или `2026-10-20T09:30:00.000Z`); идентификаторы — UUID. Файлы загружаются как `multipart/form-data`, отчёты и выгрузки отдаются файлом (`Content-Disposition: attachment`).
- **Размер тела.** JSON — не больше 2 МБ, загружаемый файл — не больше 20 МБ.
- **Кэширование.** Ответы содержат персональные данные и отдаются с заголовком `Cache-Control: no-store`.

## Вход и сессия

1. `POST /api/auth/login` с телом `{ "login": "...", "password": "..." }` возвращает `accessToken` (срок жизни — 15 минут по умолчанию, поле `expiresIn` в секундах) и сведения о пользователе. Одновременно сервер ставит две cookie: `iot_refresh` (httpOnly, Secure, SameSite=Strict) — для продления сессии, и `iot_csrf` — CSRF-токен.
2. Все остальные запросы передают токен в заголовке `Authorization: Bearer <accessToken>`.
3. Когда токен истёк (ответ 401), `POST /api/auth/refresh` выдаёт новый. Этот запрос и `POST /api/auth/logout` аутентифицируются cookie `iot_refresh`, поэтому требуют заголовок `X-CSRF-Token` со значением cookie `iot_csrf` (защита double submit). Refresh-токен при каждом обновлении заменяется новым.
4. Если у пользователя временный пароль (`mustChangePassword: true`), до смены пароля через `POST /api/auth/change-password` остальные маршруты отвечают 403.

Без входа доступны только вход, обновление сессии, выход и `GET /api/health`. Ограничения входа (число попыток, блокировка, срок сессии) настраиваются администратором — см. [../guides/admin.md](../guides/admin.md).

## Права доступа

Каждый маршрут требует разрешения (например, `students.read`, `trajectories.approve`); список разрешений и их распределение по ролям — [../architecture/access-model.md](../architecture/access-model.md). Кроме разрешения сервер проверяет область данных: преподаватель получает только студентов групп и дисциплин, за которыми закреплён, студент — только свои данные, исследователь — только обезличенные данные.

| Код | Значение                                                                                           |
| --- | -------------------------------------------------------------------------------------------------- |
| 401 | Нет входа или токен истёк                                                                          |
| 403 | Нет разрешения на действие (или пароль нужно сменить)                                              |
| 404 | Запись не существует **или** находится вне области данных пользователя — эти случаи не различаются |

## Повторная отправка форм

Маршруты, создающие записи по формам (студент, методика, назначение, сдача задания, сообщение и т. д.), требуют заголовок `Idempotency-Key` — случайную строку от 8 до 100 символов (латинские буквы, цифры, `-`, `_`), новую для каждой формы. Повтор запроса с тем же ключом в течение суток возвращает прежний результат и не создаёт дубль; тот же ключ с другим телом запроса — ответ 409. Какие маршруты требуют ключ, указано в `openapi.json` (параметр `Idempotency-Key`).

## Ошибки

Ошибки имеют единый формат:

```json
{
  "statusCode": 400,
  "message": "Проверьте правильность заполнения формы",
  "fields": { "groupId": "Выберите группу" }
}
```

`message` — понятное пользователю сообщение на русском языке, `fields` — ошибки отдельных полей (только для 400). Технические подробности и персональные данные в ответ не попадают.

| Код | Когда                                                                                                  |
| --- | ------------------------------------------------------------------------------------------------------ |
| 400 | Ошибка в данных запроса                                                                                |
| 409 | Конфликт: запись уже существует, опубликованную версию нельзя изменить, повтор ключа с другими данными |
| 413 | Слишком большое тело запроса или файл                                                                  |
| 423 | Вход временно заблокирован после неудачных попыток                                                     |
| 429 | Слишком много запросов входа с одного адреса                                                           |
| 500 | Внутренняя ошибка сервера (подробности — только в журнале сервера)                                     |

## Пример

```sh
# Вход: токен из ответа сохраняется в переменную
TOKEN=$(curl -s https://iot.example.local/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"login":"teacher","password":"<пароль>"}' | jq -r .accessToken)

# Список студентов своих групп
curl -s https://iot.example.local/api/students -H "Authorization: Bearer $TOKEN"
```

Адрес `iot.example.local` — пример; подставьте адрес сервера колледжа.
